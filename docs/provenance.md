# Provenance

Append-only ledger of changes to this plugin.

- 2026-11-10: initial plugin. Nesting rule copied from the DeepSeek harness workspace browser (`owningParentFolder` in `@deepseek-ai/dsh-client-ui-workspace` 0.2.2, nearest strict directory ancestor, case-sensitive). Rendered as a plugin screen because `addSidebarView` is on Paseo main (commit a449271d, 2026-11-07) but absent from the 0.15.4 SDK on npm. Verified: `bun test` (2 pass), `bun run typecheck` clean, `paseo plugin install` on daemon 0.15.3 reports `running`. Requested by the repository owner.
- 2026-11-10: replaced the separate tree screen with in-place nesting of the built-in sidebar list, on the owner's request ("should integrate into the existing workspace list, not a new page"). Sidebar structure read from the Paseo 0.15.3 web UI: sections are children of one flex column, each project row has test id `sidebar-project-row-host:<serverId>:<directory>`, a folded project's `role=group` keeps one child. Verified on a throwaway daemon (0.15.3, web UI, six sample projects) in headless Chrome: order and indent applied (`acme` > `api` > `sdk`), folding `api` hides `sdk`, folding `acme` hides all four descendants, disabling the plugin clears every style, re-enabling restores them. `bun test` 2 pass, `bun run typecheck` clean. Not checked: the Electron app window, drag reordering, non-directory projects. `assets/screenshot.png` is from that sample daemon.
- 2026-11-10: tightened the list's vertical spacing on the owner's request ("make the margins top down thinner"). Measured in the Paseo 0.15.3 web UI: section bottom padding 12px, project row 8px padding and 4px margin, workspace row 8px padding and 2px margin, 36px minimum row height. A stylesheet scoped to the sidebar list sets 28px minimum height, 4px padding, no row margin and a 2px section gap. Verified on the throwaway daemon in headless Chrome: each one-workspace section went from 94px to 62px, and back to 94px with the plugin disabled. `bun test` 2 pass, `bun run typecheck` clean. `assets/screenshot.png` retaken.
- 2026-11-10: fixed git projects not nesting, reported by the owner with a screenshot of their sidebar ("i dont see nesting here"): only plain folders nested. Cause: a git project with a remote has the sidebar key `remote:<host>/<owner>/<repo>`, and the plugin read directories out of `host:<serverId>:<directory>` keys only. Directories now come from `paseo.projects.list()`, whose `projectKey` equals the row test id suffix (checked against a 0.15.3 daemon: `remote:github.com/example/acme-web` with `projectRootPath` set). The list is read at start and again when a row with an unlisted key appears. Verified on the throwaway daemon in headless Chrome with four git projects: `web`, `bare` nest under `acme`, `ui` under `web`, and a git project created while the page was open nested within 3 seconds without a reload. `bun test` 4 pass, `bun run typecheck` clean. Not checked: the owner's Electron window, two hosts with the plugin at once. `assets/screenshot.png` retaken.
